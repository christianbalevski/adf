# Phase 4 — Interactive HTTP OAuth for remote MCP servers

Lets a user add/attach a remote (`type: 'http'`) MCP server whose endpoint requires OAuth and complete a **browser consent flow** instead of pasting a bearer token. Unlocks OAuth-DCR remotes (Linear, Cloudflare, GitHub remote, Atlassian, Notion remote, official Slack, Asana, Sentry, Neon, Hugging Face, GitLab, ClickUp, Supabase, Todoist, Readwise). Vercel stays out (client-allowlisted).

## SDK: no work needed
`@modelcontextprotocol/sdk` **1.27.1** (installed) has full client OAuth:
- `OAuthClientProvider` interface — `client/auth.d.ts`. App implements: `redirectUrl`, `clientMetadata`, `clientInformation()/saveClientInformation()` (saveClientInformation REQUIRED for DCR), `tokens()/saveTokens()`, `redirectToAuthorization()`, `saveCodeVerifier()/codeVerifier()`, `state?()`, `invalidateCredentials?()`, `saveDiscoveryState?()/discoveryState?()`.
- `auth(provider, { serverUrl, authorizationCode?, scope? })` → `'AUTHORIZED' | 'REDIRECT'`. Does RFC 9728 → RFC 8414/OIDC discovery → RFC 7591 DCR → refresh → PKCE `startAuthorization` → `redirectToAuthorization`. Called again with `authorizationCode` → token exchange → `'AUTHORIZED'`.
- `StreamableHTTPClientTransport` accepts `authProvider` (`client/streamableHttp.d.ts`): sets `Authorization: Bearer` from `tokens()`, and auto-calls `auth()` on 401/expiry then `saveTokens()` — **refresh is transparent, main-process, every runtime that can read the store**. `UnauthorizedError` exported from `client/auth.js`. Use the `createRequire` CJS shim already in mcp-client-manager.ts (lines 21–24) to import `client/auth.js`.

## Decisions (locked)
1. **Token storage = HYBRID**: sign in once at Settings → app-level encrypted store (safeStorage) is the Studio "signed-in" source of truth; on agent **attach**, capture+seal the token into that agent's identity keystore (mirrors `captureCredentialFile`/`materializeCredentialFiles` in mcp-credential-files.ts), so it travels with the `.adf` and a daemon with a provisioned runtime key can connect + refresh. Connect prefers the agent-sealed token, falls back to the app-level token.
2. **v1 runtime = Studio-only interactive** sign-in. Daemon: works if an agent-sealed token exists + runtime key provisioned (refresh included); otherwise fail plainly: `Remote MCP server "X" requires OAuth — sign in once from ADF Studio → Settings` (mirror the envelope-locked message in mcp-credential-files.ts). No headless DCR/loopback on the daemon host.
3. **Dual-mode entries** (github, linear, atlassian-cloud, cloudflare-bindings, cloudflare-observability, neon, huggingface): OAuth default, KEEP the `bearerTokenEnvVar` paste-token fallback (CI/daemon users). Entry offers "Sign in" OR paste token.
4. **Callback = ephemeral loopback port + fresh DCR per sign-in** (no fixed port → no EADDRINUSE class; DCR is free). Bind 127.0.0.1 only, validate `state`, single-use code, ~5 min timeout, only open https authorization URLs from SDK discovery.

## Flow (preflight-style, matches runMcpAuthPreflight architecture)
Before connect, if `config.oauth` and no valid token: `auth(provider, { serverUrl })` → on `'REDIRECT'`, provider `redirectToAuthorization` does `shell.openExternal`, the loopback callback server awaits `code` (+state check) → `auth(provider, { serverUrl, authorizationCode })` → `'AUTHORIZED'`. Connect then runs with `authProvider` on the transport (header attach + silent refresh). No confirm dialog — the callback is deterministic completion. Interactivity stays OUT of `McpClientManager` (it just gets an `authProvider`).

## Security invariants
- Tokens sealed like credentials: app store via safeStorage `setSecret`; agent copy envelope-sealed. NEVER plaintext in `mcpServers`/`adf-settings.json` or the `.adf` agent config. `mcpOauthCredentials` joins `SETTINGS_SECRET_KEYS` + `SETTINGS_WRITE_DENY_KEYS` (daemon http-api.ts) and the `SettingsService.getAll()` delete list.
- No token in argv (no child process here — inherent) or logs (McpClientManager.addLog logs URLs/status only — keep it that way; log URLs without query).
- Tokens never enter `serverCfg.env`/`headers` (transport attaches Authorization internally) → agent/sandbox code can never read them; refresh is main-process only. Add a test asserting no token reaches `sys_get_config` output.
- Executable-identity pinning: `oauth` + `url` come from the registration via `pinServerConfigToRegistration` — tokens are keyed by the PINNED url, so a tampered `.adf` can't redirect them.
